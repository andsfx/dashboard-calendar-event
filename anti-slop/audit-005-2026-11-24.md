**Tanggal:** 2026-11-24  
**Scope:** `src/pages/SurveyHubPage.tsx`, `src/components/nav/publicNav.ts`, `src/App.tsx` (route `/survei`, redirect `/survey`, back-link `/tenant-survey`)

## Smoke browser (bukti)

- `/survei` desktop: render OK; heading "Pusat survei event", pencarian "Cari event", dua section (tenant/EO), skip link ada. Data API lokal gagal (dev tanpa backend) → dua alert error + tombol "Coba lagi" tampil, bukan crash. Screenshot: `.tmp` dibuat saat smoke lalu dihapus.
- `/survei` mobile 390×844 + dark: layout menumpuk satu kolom, CTA header masuk menu, search/section/error states tetap terbaca.
- `/tenant-survey`: back-link berubah menjadi "Pusat survei" menuju `/survei` (sebelumnya ke beranda).
- `/survey/test-event?type=organizer`: route render; gagal memuat data event karena ID uji tidak ada, tapi halaman/form shell tidak crash.

## Temuan

### 1. [P2][Medium] Dua alert error paralel bersaing sebagai live region
- **Lokasi:** `src/pages/SurveyHubPage.tsx:119-123`, `151-155`
- **Bukti:** Saat kedua fetch gagal, snapshot a11y menunjukkan dua `alert` terpisah ("Gagal memuat event survei tenant." dan "Gagal memuat daftar event.") masing-masing dengan tombol "Coba lagi" sendiri.
- **Dampak:** Screen reader mendapat dua assertive alert dalam render yang sama; pengguna melihat dua pemulihan terpisah untuk kegagalan yang asalnya satu konteks halaman (koneksi/API lokal). Beban kognitif naik tanpa informasi baru.
- **Arah perbaikan:** Pertimbangkan satu status/error ringkas tingkat halaman, atau jadikan alert non-assertive/per-section dengan copy yang membedakan aksi; jika tombol retry tetap terpisah, jelaskan cakupannya.

### 2. [P2][Medium] Tombol "Coba lagi" memuat ulang kedua sumber tanpa membedakan scope
- **Lokasi:** `src/pages/SurveyHubPage.tsx:44,52-70,122,154`
- **Bukti:** Satu `retryKey` dipakai bersama; klik "Coba lagi" pada section tenant memicu ulang `fetchEvents()` dan `fetchPublicTenantSurveyEvents()`.
- **Dampak:** Retry yang tampak lokal sebenarnya global. Bisa menimpa state section yang sudah berhasil, menambah request tak perlu, dan membingungkan saat salah satu sumber flakey.
- **Arah perbaikan:** Pisahkan retry per sumber (`retryTenantKey`/`retryEventsKey`) atau satu handler yang hanya mengulang sumber gagal.

### 3. [P2][Low] Label "Coba lagi" duplikat tanpa nama kontekstual
- **Lokasi:** `src/pages/SurveyHubPage.tsx:122,154`
- **Bukti:** Dua tombol punya nama aksesibel identik "Coba lagi" di halaman yang sama.
- **Dampak:** Pengguna screen reader yang menelusur daftar tombol mendapat dua kontrol identik; tujuan tiap tombol tidak jelas tanpa konteks region.
- **Arah perbaikan:** Beri `aria-label` spesifik, mis. "Coba muat survei tenant lagi" / "Coba muat event survei EO lagi", atau sertakan teks visually-hidden.

### 4. [P3][Low] Link "Lihat semua event tenant" duplikatif secara navigasi
- **Lokasi:** `src/pages/SurveyHubPage.tsx:142-144`
- **Bukti:** Section tenant selalu merender link "Lihat semua event tenant" ke `/tenant-survey`, termasuk saat daftar event tenant aktif sudah ditampilkan penuh di atasnya.
- **Dampak:** Di state sukses, link menambah noise dan mengulang tujuan yang baru saja disajikan; pengguna bisa mengira ada event lain yang belum ditampilkan.
- **Arah perbaikan:** Tampilkan hanya saat daftar dipotong/di-ringkas, atau ganti dengan microcopy yang menjelaskan bedanya dengan daftar di atas. Jika hub memang pintu masuk, pertahankan tapi bedakan labelnya.

### 5. [P3][Low] `/survey` redirect mengorbankan deep-link event
- **Lokasi:** `src/App.tsx:525`
- **Bukti:** `<Route path="/survey" element={<Navigate to="/survei" replace />} />` menangani `/survey` tanpa `:eventId`; route `/survey/:eventId` tetap ada di bawahnya.
- **Dampak:** Pengguna/tautan lama ke `/survey` (tanpa id) diarahkan benar ke hub. Ini aman, tapi tidak ada affordance bagi pengguna yang salah mengetik `/survey/<id-lama-tanpa-type>` atau berharap hub bisa menerima query. Risiko kecil; utamanya catatan perilaku.
- **Arah perbaikan:** Tidak wajib. Bila ada trafik lama ke pola `/survey?...`, pertimbangkan mempertahankan query string saat redirect.

### 6. [P3][Medium] Back-link `/tenant-survey` kini selalu ke `/survei`, bukan konteks asal
- **Lokasi:** `src/App.tsx:549-551`
- **Bukti:** Link di header halaman tenant survey diubah dari "Kembali ke Beranda" (`/`) menjadi "Pusat survei" (`/survei`).
- **Dampak:** Masuk akal untuk alur baru lewat hub, tapi pengguna yang datang dari beranda, direct link, atau bookmark kehilangan jalan kembali yang netral. Untuk form publik anonim, back-link yang terlalu spesifik bisa terasa seperti langkah mundur yang salah.
- **Arah perbaikan:** Pertimbangkan label/tujuan kontekstual (mis. "Kembali" dengan `navigate(-1)` aman bila ada history internal, fallback ke `/survei`), atau tetapkan `/survei` sebagai canonical hub dan terima trade-off ini eksplisit.

### 7. [P2][Low] Pencarian satu kotak memfilter dua section dengan hasil kosong yang bisa asimetris
- **Lokasi:** `src/pages/SurveyHubPage.tsx:73-80,106-116,124-197`
- **Bukti:** Satu input `query` memfilter `filteredTenantEvents` dan `filteredEvents` secara independen. Masing-masing section menampilkan empty state sendiri.
- **Dampak:** Pengguna bisa melihat satu section kosong dan satu terisi tanpa ringkasan; saat keduanya kosong, dua empty state identik ("Event tidak ditemukan") muncul. Bukan bug, tapi menambah scan cost.
- **Arah perbaikan:** Tambahkan ringkasan hasil kecil ("2 event cocok") atau satu empty state gabungan saat kedua section kosong karena query.
