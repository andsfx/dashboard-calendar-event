Latar Belakang

Tantangan operasional sehari-hari.

Operasional event berjalan terpisah-pisah: data tersebar, proses manual, evaluasi tidak terhubung.

  • 01Fragmentasi data — jadwal tersebar di berbagai media, risiko miskomunikasi.
  • 02Visibility rendah — distribusi event sulit dipantau; overlap baru ketahuan saat bentrok.
  • 03Pengajuan manual — pendaftaran komunitas & upload proposal belum terpusat.
  • 04Evaluasi terfragmentasi — survey pengunjung dan tenant terpisah, sulit direkap.
  • 05Dokumentasi tidak efisien — surat resmi dan dokumentasi area masih manual.
Satu jadwal event = biaya koordinasi tersembunyi02

Fitur Unggulan · Tenant

Self-assessment anonim.

Tenant menilai dampak event terhadap gerainya — tanpa login, hasil terkumpul otomatis.

Alur pengisian

Tiga langkah, nol akun

Buka /tenant-survey → pilih event (Event Picker) → isi form di /tenant-survey/:eventId. Pilih gerai dari daftar MID, isi skala kenaikan traffic & sales, kirim.

Hasil agregat

Terbuka & real-time

/tenant-survey-results — dashboard publik read-only: KPI traffic/sales, filter event, tren per bulan. Admin/TR bisa ekspor PDF.

Anti-spam

Fingerprint + rate limit

Deteksi duplikat per device+event, rate limit IP server-side, konfigurasi per-event (buka/tutup form) — default tertutup.

Manfaat

Insight objektif

Data dampak event ke traffic/sales gerai — bahan evaluasi & negosiasi sponsorship, tanpa admin jadi perantara.

Feedback loop tenant → data agregat → keputusan event berikutnya07

Keamanan & Kualitas

Empat lapis jaminan.

Audit trail

6 jenis aksi tercatat otomatis di Log Aktivitas: Membuat, Mengubah, Menghapus, Login, Logout, Mengundang — lengkap IP, user, dan timestamp.

Automated testing

47 file test Vitest (status event, permission matrix, validasi form, publish Draft→Event) + 4 E2E Playwright untuk alur tenant survey.

Validasi di setiap boundary

Zod schemas memvalidasi payload di klien dan server — schema yang sama, tidak ada celah validasi ganda.

Status tidak bisa basi

Status event diderivasi dari tanggal (zona Asia/Jakarta) — tidak ada status salah karena lupa update manual. RLS menjaga channel publik vs admin.

RBAC · Audit trail · 47 test file · zod di setiap boundary11
